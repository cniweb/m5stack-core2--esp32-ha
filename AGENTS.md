# AGENTS.md

High-signal context for AI agents working on `m5stack-core2--esp32-ha`.

## Commands

- **Build / Check**: `pio run` (automatically runs `scripts/ha_rest_preflight.py` first)
- **Upload**: `pio run -t upload --upload-port COM8` (COM8 is the verified local port)
- **Monitor**: `pio device monitor --port COM8 --baud 115200`
- **Lint Docs**: `npx markdownlint-cli2 "**/*.md" "#node_modules" "#.pio" --fix`
- **Tests / C++ Lint**: No unit test framework or C++ linter configured. Validation is strictly `pio run` and hardware flashing.

## Architecture & Quirks

- **Stack**: Arduino, PlatformIO, ESP32, M5Stack Core2 (`M5Unified` library).
- **Backend**: Direct REST API to Home Assistant (no ESPHome).
- **REST Parsing**: The firmware extracts `"state":"..."` directly from the HTTP response text. Do **not** replace this with an `ArduinoJson` parser (string parsing proved more reliable on-device to avoid OOM/fragmentation).
- **Preflight Check**: `scripts/ha_rest_preflight.py` blocks `pio run` if HA is unreachable, the token is missing, or required entities are missing.
- **Home Assistant Entities**: The device depends on custom entities generated by `home-assistant/packages/core2_power_history.yaml`.
- **Secrets**: `include/secrets.h` is gitignored. Use `include/secrets.example.h` as a template. Do not commit tokens or Wi-Fi credentials.

## UI & Layout Rules

- **Shared Grid**: Enforce a strict 12px grid (outer margins, gaps between cards/rows).
- **Centering**: Use shared `constexpr` inset constants in `src/main.cpp` for text alignment. Avoid manually tweaking coordinates per-page.
- **Compile-Time Safety**: Use `static_assert` for layout constants in `src/main.cpp` to prevent geometric overlaps at compile time.
- **Touch & Idle**: Wake logic must tolerate held touches. The screen uses a dim backlight (`kSleepBrightness = 1`) for idle mode rather than full off, as it's more reliable for touch-wake on the Core2.

## Workflow Expectations

- **Documentation**: Keep `README.md` concise. Put detailed instructions in `docs/` and use relative markdown links.
- **Verification**: Do not claim success until `pio run` passes locally.
- **Git Flow**: Standard workflow after local verification is: `git commit`, `git push`, then use `gh run list --limit 1` to ensure the GitHub Actions CI build passes.
